# ProConfigProvider

`ProConfigProvider` supplies shared configuration to ProComponents in its
subtree. Use it to override theme tokens, enable dark mode, register custom
`valueType` renderers, or configure localized text.

Continue to use antd's `ConfigProvider` for antd components. `ProConfigProvider`
reads the surrounding antd configuration and passes the relevant theme and
locale information to ProComponents.

## Basic usage

```tsx | pure
import { ProConfigProvider, ProTable } from '@ant-design/pro-components';
import { ConfigProvider } from 'antd';
import enUS from 'antd/locale/en_US';

export default () => (
  <ConfigProvider locale={enUS} theme={{ token: { borderRadius: 6 } }}>
    <ProConfigProvider token={{ colorPrimary: '#722ed1' }}>
      <ProTable
        columns={[]}
        request={async () => ({ data: [], success: true })}
      />
    </ProConfigProvider>
  </ConfigProvider>
);
```

Nested `ProConfigProvider` instances inherit their parent configuration and
merge `token` values. The nearest explicit setting takes precedence.

## Zero runtime styles (antd 6)

When the outer `ConfigProvider` sets `theme.zeroRuntime: true`, ProComponents
also stops registering component styles in the browser. For the default `ant`
prefix and theme, import the official CSS directly:

```tsx | pure
// Application entry, before component styles
import 'antd/dist/antd.css';
import '@ant-design/pro-components/dist/pro-components.css';
// pro-components.min.css is also available for production
import { ProCard } from '@ant-design/pro-components';
import { ConfigProvider } from 'antd';

export default () => (
  <ConfigProvider theme={{ hashed: false, cssVar: {}, zeroRuntime: true }}>
    <ProCard title="Example">Content</ProCard>
  </ConfigProvider>
);
```

The official CSS uses antd 6 cssVar. Colors, borders, alpha-derived colors, and
layout backgrounds follow `--ant-*` variables. Keep the static CSS and
application aligned on `hashed: false`, and import antd's official CSS
separately.

For a custom prefix or theme, extract the complete manifest during the Node
build. `prefixCls` is also the default CSS variable prefix; `zeroRuntime` is
disabled only inside the isolated extraction tree:

```tsx | pure
// scripts/extract-pro-style.tsx
import { writeFileSync } from 'node:fs';
import { extractAllProStyle } from '@ant-design/pro-components/static-style-extract';

const css = extractAllProStyle({
  prefixCls: 'topiam',
  customTheme: {
    cssVar: { prefix: 'topiam' },
    token: { colorPrimary: '#123456' },
    zeroRuntime: true,
  },
});
writeFileSync('src/pro-components.css', css);
```

Run this script before the application build, for example with
`npx tsx scripts/extract-pro-style.tsx`, and import the generated
`src/pro-components.css` in your application entry (alongside your extracted
antd CSS). Use
`<ConfigProvider prefixCls="topiam" theme={{ hashed: false, cssVar: { prefix: 'topiam' }, token: { colorPrimary: '#123456' }, zeroRuntime: true }}>`
in the application so classes, variables, and theme settings match the
extraction.

`extractAllProStyle` covers the SSR-renderable states of the built-in Layout,
Table, Form, Descriptions, Card, List, Field, Skeleton, and common utility
components. Use `includes` / `excludes` with stable component names to filter
the manifest. `customizeRender` can replace a built-in scenario or add
application-specific states, and `wrap` can add application providers. The
default return value is plain CSS without `<style>` tags (`plain: true`). SSR
does not run effects or interactions, so custom value types, asynchronous
fields, and states revealed by interaction should be added through
`customizeRender`.

The existing `extractProStyle(node)` is unchanged: it only extracts the supplied
tree and does not automatically disable `zeroRuntime`. Themes with different
structural styles need corresponding static CSS. As in antd, `zeroRuntime` is
selected on the first mount; changing it requires remounting the styled subtree.

## Custom value types

`valueTypeMap` registers read and edit renderers for ProField based components
such as ProTable, ProDescriptions, and ProFormField.

```tsx | pure
import { ProConfigProvider, ProTable } from '@ant-design/pro-components';
import { Input, Tag } from 'antd';

const valueTypeMap = {
  badgeText: {
    render: (text: unknown) => <Tag color="blue">{String(text ?? '')}</Tag>,
    formItemRender: (_text: unknown, props: any) => (
      <Input {...props.fieldProps} />
    ),
  },
};

export default () => (
  <ProConfigProvider valueTypeMap={valueTypeMap}>
    <ProTable
      columns={[{ dataIndex: 'status', valueType: 'badgeText' as any }]}
    />
  </ProConfigProvider>
);
```

Custom strings are outside the built in `ProFieldValueType` union, so the
example uses a local type assertion on the column.

## API

| Property         | Description                                                                         | Type                                      | Default                                          |
| ---------------- | ----------------------------------------------------------------------------------- | ----------------------------------------- | ------------------------------------------------ |
| `children`       | Descendants that receive the configuration                                          | `ReactNode`                               | -                                                |
| `token`          | ProComponents token overrides, including antd global tokens and ProLayout tokens    | `DeepPartial<ProAliasToken>`              | `{}`                                             |
| `valueTypeMap`   | Registers or overrides read and edit renderers for a `valueType`                    | `Record<string, ProRenderFieldPropsType>` | `{}`                                             |
| `dark`           | Enables or disables the dark algorithm on top of the current antd theme             | `boolean`                                 | inherited                                        |
| `hashed`         | Controls hashed class names for ProComponents styles                                | `boolean`                                 | `true` in production                             |
| `prefixCls`      | CSS class prefix for ProComponents                                                  | `string`                                  | derived from antd `prefixCls`                    |
| `intl`           | Explicit ProComponents messages; normally inferred from the surrounding antd locale | `IntlType`                                | inferred from antd locale, then Chinese fallback |
| `autoClearCache` | Uses an isolated SWR cache and clears it when the provider unmounts                 | `boolean`                                 | `false`                                          |
| `needDeps`       | Internal dependency marker used to avoid redundant providers                        | `boolean`                                 | `false`                                          |

## Recommendations

- Put application wide theme and locale settings near the root. Nest a provider
  only when a subtree needs different styling or renderers.
- Use `hashed={false}` only when stable class names are required for debugging
  or a specific integration. The default reduces style collisions in production.
- Use `autoClearCache` for tests, micro frontends, or subtrees whose request
  cache must be discarded on unmount. Most applications can omit it.
- `needDeps` is intended for library internals and is unnecessary in application
  code.
