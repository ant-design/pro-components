# ProConfigProvider

`ProConfigProvider`
为其子树中的 ProComponents 提供统一配置。常见用途包括覆盖主题 Token、切换深色主题、注册自定义
`valueType` 和配置国际化。

应用仍应使用 antd 的 `ConfigProvider` 配置 antd 组件。`ProConfigProvider`
会读取外层 antd 配置，并把相关主题和语言信息传给 ProComponents。

## 基础用法

```tsx | pure
import { ProConfigProvider, ProTable } from '@ant-design/pro-components';
import { ConfigProvider } from 'antd';
import zhCN from 'antd/locale/zh_CN';

export default () => (
  <ConfigProvider locale={zhCN} theme={{ token: { borderRadius: 6 } }}>
    <ProConfigProvider token={{ colorPrimary: '#722ed1' }}>
      <ProTable
        columns={[]}
        request={async () => ({ data: [], success: true })}
      />
    </ProConfigProvider>
  </ConfigProvider>
);
```

嵌套的 `ProConfigProvider` 会继承外层配置，并合并
`token`。离组件最近的显式配置优先。

## 零运行时样式（antd 6）

外层 `ConfigProvider` 设置 `theme.zeroRuntime: true`
后，ProComponents 也会停止在浏览器中注册组件样式。默认 `ant`
前缀和默认主题可直接引入官方产物：

```tsx | pure
// 应用入口，在组件样式之前引入
import 'antd/dist/antd.css';
import '@ant-design/pro-components/dist/pro-components.css';
// 生产环境也可以引入 pro-components.min.css
import { ProCard } from '@ant-design/pro-components';
import { ConfigProvider } from 'antd';

export default () => (
  <ConfigProvider theme={{ hashed: false, cssVar: {}, zeroRuntime: true }}>
    <ProCard title="Example">Content</ProCard>
  </ConfigProvider>
);
```

官方 CSS 使用 antd 6 cssVar，颜色、边框、透明度派生色及布局背景会随 `--ant-*`
变量切换。请保持静态 CSS 与应用的 `hashed: false`
配置一致，并单独引入 antd 官方样式。

自定义前缀或主题时，在 Node 构建流程中使用全量抽取。`prefixCls`
会同时作为默认 CSS 变量前缀，`zeroRuntime` 仅在抽取子树中临时关闭：

```tsx | pure
// scripts/extract-pro-style.tsx
import { writeFileSync } from 'node:fs';
import { extractAllProStyle } from '@ant-design/pro-components/static-style-extract';

const css = extractAllProStyle({
  prefixCls: 'topiam',
  customTheme: {
    cssVar: { prefix: 'topiam' },
    token: { colorPrimary: '#123456' },
    zeroRuntime: true,
  },
});
writeFileSync('src/pro-components.css', css);
```

先在应用构建前运行该脚本，例如
`npx tsx scripts/extract-pro-style.tsx`，并在应用入口导入生成的
`src/pro-components.css`（与按相同前缀抽取的 antd 样式一起引入）。应用中使用
`<ConfigProvider prefixCls="topiam" theme={{ hashed: false, cssVar: { prefix: 'topiam' }, token: { colorPrimary: '#123456' }, zeroRuntime: true }}>`，使类名、变量及主题配置与抽取时一致。

`extractAllProStyle`
默认覆盖内置 Layout、Table、Form、Descriptions、Card、List、Field、Skeleton 和常用控件的 SSR 可渲染状态。可用
`includes` / `excludes` 筛选稳定组件名；`customizeRender`
可覆盖某个内置场景或补充业务特有状态，`wrap` 可添加应用 Provider，返回默认是无
`<style>`
标签的纯 CSS（`plain: true`）。SSR 不会执行交互和 effect，业务自定义 valueType、异步字段或交互后才出现的状态应通过
`customizeRender` 补充。

原有的 `extractProStyle(node)`
保持兼容：它只抽取调用方提供的组件树，不会自动关闭
`zeroRuntime`。切换结构不同的主题时，需要提供对应的静态 CSS；`zeroRuntime`
在组件首次挂载时确定，运行中更改需要重新挂载组件树。

## 自定义 valueType

`valueTypeMap`
可以为 ProTable、ProDescriptions、ProFormField 等基于 ProField 的组件注册展示态和编辑态渲染器。

```tsx | pure
import { ProConfigProvider, ProTable } from '@ant-design/pro-components';
import { Input, Tag } from 'antd';

const valueTypeMap = {
  badgeText: {
    render: (text: unknown) => <Tag color="blue">{String(text ?? '')}</Tag>,
    formItemRender: (_text: unknown, props: any) => (
      <Input {...props.fieldProps} />
    ),
  },
};

export default () => (
  <ProConfigProvider valueTypeMap={valueTypeMap}>
    <ProTable
      columns={[{ dataIndex: 'status', valueType: 'badgeText' as any }]}
    />
  </ProConfigProvider>
);
```

自定义字符串不在内置 `ProFieldValueType`
联合类型中，因此示例在 column 上使用了局部类型断言。

## API

| 参数             | 说明                                                              | 类型                                      | 默认值                              |
| ---------------- | ----------------------------------------------------------------- | ----------------------------------------- | ----------------------------------- |
| `children`       | 使用配置的子节点                                                  | `ReactNode`                               | -                                   |
| `token`          | 覆盖 ProComponents Token；支持 antd 全局 Token 和 ProLayout Token | `DeepPartial<ProAliasToken>`              | `{}`                                |
| `valueTypeMap`   | 注册或覆盖 `valueType` 的展示态和编辑态渲染器                     | `Record<string, ProRenderFieldPropsType>` | `{}`                                |
| `dark`           | 在当前 antd 主题算法上启用或关闭深色算法                          | `boolean`                                 | 继承外层配置                        |
| `hashed`         | 是否为 ProComponents 样式生成 hash 类名                           | `boolean`                                 | 生产环境为 `true`                   |
| `prefixCls`      | ProComponents CSS 类名前缀                                        | `string`                                  | 基于 antd `prefixCls` 生成          |
| `intl`           | 显式设置 ProComponents 文案；通常可由外层 antd `locale` 自动推导  | `IntlType`                                | 根据 antd locale 推导，最后回退中文 |
| `autoClearCache` | 使用独立 SWR 缓存，并在 Provider 卸载时清空                       | `boolean`                                 | `false`                             |
| `needDeps`       | ProComponents 内部用于避免重复 Provider 的依赖标记                | `boolean`                                 | `false`                             |

## 使用建议

- 主题和语言的应用级配置放在根节点；仅在局部需要不同样式或渲染器时嵌套 Provider。
- `hashed={false}`
  适合需要稳定类名的调试或特殊集成场景。生产环境通常保留默认值，以减少样式冲突。
- `autoClearCache`
  适合测试、微应用或需要在卸载时隔离请求缓存的子树。普通应用无需设置。
- `needDeps` 供组件库内部使用，业务代码无需设置。
